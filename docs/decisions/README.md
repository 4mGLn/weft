# Architecture Decision Records

Use numbered ADRs for durable choices affecting domain invariants, public contracts, provider mappings, persistence, concurrency, recovery, security, compatibility, or deployment.

Each ADR records status, context, decision, alternatives, consequences, migration or rollback, and required proof. ADRs explain decisions; `DOMAIN.md` remains the normative behavior source and must be updated in the same change when an accepted decision changes it.
